# Frequency Sweep Functioning Code Runbook

**Scope:** this runbook describes the working plain-Spectre frequency-sweep code path for the `thesis_reorg` branch.

The current flow is organized as one experiment:

```text
experiments/frequency_sweep/
```

with input data, OCEAN scripts, and shell helpers separated into experiment-local directories.

---

## 2. Primary entry point

### `experiments/frequency_sweep/bin/spectre_sweep_plain_reorg_v3.sh`

Purpose:

- Creates one timestamped run directory under `database/`.
- Writes `RUNINFO.txt` with all paths and runtime parameters.
- Generates `cases.csv` from `input_data/spike_train_output/st_1` and `st_2`.
- Copies helper scripts into the run directory.
- Generates run-local scripts:
  - `import_template.sh`
  - `run_template_ocean.sh`
  - `ciw_template_command.il`
  - `monitoring_commands.sh`
  - `select_cases.py`
- Copies `export_psf_to_txt.ocn` into the run-local `ocn/` directory.

Normal invocation:

```bash
cd /home/s5117909/Documents/thesis/thesis_codebase
git checkout thesis_reorg

NUM_JOBS=4 RUN_LABEL=2channel_1syn_plain \
./experiments/frequency_sweep/bin/spectre_sweep_plain_reorg_v3.sh prep
```

Important environment variables:

| Variable | Default / meaning |
|---|---|
| `NUM_JOBS` | Number of parallel workers; default is `4` |
| `RUN_LABEL` | Human-readable suffix in the run directory name |
| `RUN_ID` | Optional explicit run directory name |
| `REPO_DIR` | Repository root; auto-detected with Git |
| `EXP_DIR` | Frequency-sweep experiment path |
| `SPIKE_DIR` | `experiments/frequency_sweep/input_data/spike_train_output` |
| `DATABASE_DIR` | `database/` under repo root |
| `NETLIST_SOURCE` | Existing Cadence-generated Spectre netlist directory |
| `CADENCE_INSTALL_ROOT` | `/projects/bics/cadence/installs` |
| `IC_VERSION` | Usually `IC231` |

## 5. Script-by-script explanation

### 5.1 `import_template.sh`

Generated by the prep script inside each run directory.

Purpose:

1. Copies an existing Cadence-generated Spectre netlist from `NETLIST_SOURCE` into:

   ```text
   netlist_template/raw/
   ```

2. Replaces spike-train PWL paths with placeholders:

   ```text
   __ST1_PWL__
   __ST2_PWL__
   ```

3. Rewrites the top-level `parameters` statement in `input.scs` with explicit values:

   ```spectre
   m2w=3u m2l=200n
   m3w=2.1u m3l=4u
   m4w=2.1u m4l=1.05u
   m5w=2.1u m5l=1.05u
   m4wtb=2.1u m4ltb=1.05u
   m2wtb=2.1u m2ltb=1.05u
   pw=100u T=1m Vin=0 vmax=1.8
   Vw=0.5 Vthr=0.9 Vtau=1.6
   capacitance=6p
   pwlFile_st2=__ST2_PWL__
   pwlFile_st1=__ST1_PWL__
   ```

4. Writes `.designVariables` for traceability.

Preflight verification:

```bash
./import_template.sh
grep -R "__ST1_PWL__\|__ST2_PWL__" netlist_template/raw | head -20
```

Do not run workers if placeholders are absent.

---

### 5.2 `refresh_spectre_runtime.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/refresh_spectre_runtime.sh
```

Purpose:

- Finds a usable Spectre launcher, preferably the site wrapper:

  ```text
  /projects/bics/cadence/installs/SPECTRE231/tools/bin/spectre
  ```

- Finds a usable OCEAN/Virtuoso export launcher from the IC installation.
- Resolves missing shared-library paths for both launchers.
- Writes cached environment fragments:

  ```text
  support/spectre_runtime.env
  support/cadence_ic_runtime.env
  ```

Typical command:

```bash
./refresh_spectre_runtime.sh
```

Diagnostic log:

```bash
cat logs/refresh_spectre_runtime.log | tail -100
```

---

### 5.3 `setup_spectre_env.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/setup_spectre_env.sh
```

Purpose:

- Loads `RUNINFO.txt`.
- Selects or reloads `SPECTRE_CMD`.
- Sources:

  ```text
  support/spectre_runtime.env
  support/cadence_ic_runtime.env
  ```

- Defines shell functions:

  ```bash
  check_spectre_runtime
  spectre_runtime_ok
  check_export_runtime
  ```

Usage:

```bash
source ./setup_spectre_env.sh
check_spectre_runtime
check_export_runtime
```

Important distinction:

- `check_spectre_runtime` validates the Spectre simulation launcher.
- `check_export_runtime` validates the OCEAN/Virtuoso export launcher.

Both must pass before launching workers.

---

### 5.4 `run_all_workers.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/run_all_workers.sh
```

Purpose:

- Sources `RUNINFO.txt` and `setup_spectre_env.sh`.
- Refuses to proceed if Spectre runtime is unresolved.
- Refuses to proceed if the export launcher is unresolved or has missing shared libraries.
- Starts workers:

  ```text
  run_spectre_worker.sh 0
  run_spectre_worker.sh 1
  ...
  run_spectre_worker.sh NUM_JOBS-1
  ```

Case split:

```text
case_id % NUM_JOBS == job_index
```

Usage:

```bash
./run_all_workers.sh
```

---

### 5.5 `run_spectre_worker.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/run_spectre_worker.sh
```

Purpose:

For each assigned row in `cases.csv`:

1. Creates the case directory.
2. Skips the case if `output_signals.txt` already exists.
3. Copies `netlist_template/raw/` into `case/netlist/`.
4. Substitutes placeholders with quoted PWL file paths:

   ```spectre
   pwlFile_st1="/absolute/path/to/st_1/.../trial_N.pwl"
   pwlFile_st2="/absolute/path/to/st_2/.../trial_N.pwl"
   ```

5. Runs Spectre:

   ```bash
   "$SPECTRE_CMD" input.scs +escchars +log "$case_dir/spectre.out" -format psfxl -raw "$case_dir/psf"
   ```

6. Calls:

   ```bash
   ./run_export_case.sh "$case_dir"
   ```

7. Marks the case as done only if `output_signals.txt` exists.

Worker logs:

```text
logs/spectre_worker_0.log
logs/spectre_worker_1.log
...
```

Done/failed records:

```text
worker_state/job_0_done.txt
worker_state/job_0_failed.txt
...
```

---

### 5.6 `run_export_case.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/run_export_case.sh
```

Purpose:

- Takes one case directory as an argument.
- Locates the run-local OCEAN export script:

  ```text
  ocn/export_psf_to_txt.ocn
  ```

- Ensures relevant IC runtime paths are in `PATH` and `LD_LIBRARY_PATH`.
- Chooses `ocean` if available, otherwise a suitable `virtuoso` launcher.
- Runs the export with:

  ```bash
  CAD_CASE_DIR="$case_dir" CAD_BATCH_EXIT=1 "$LAUNCHER" -nograph -restore "$OCN"
  ```

- Fails if `output_signals.txt` is not created.

Per-case export log:

```text
cases/<case_name>/export_ocean.log
```

---

### 5.7 `export_psf_to_txt.ocn`

Copied into each run under:

```text
ocn/export_psf_to_txt.ocn
```

Purpose:

- Reads the case directory from:

  ```text
  CAD_CASE_DIR
  ```

- Opens:

  ```text
  CAD_CASE_DIR/psf
  ```

- Selects the transient result:

  ```lisp
  selectResult('tran)
  ```

- Exports these waveforms:

  ```lisp
  i("/I56/Iout")
  v("/vpre")
  v("/vpre1")
  ```

- Writes:

  ```text
  output_signals.txt
  ```

This script does not netlist and does not intentionally modify the schematic database. It only reads an existing PSF result and prints selected signals.

---

### 5.8 `extract_missing_outputs.sh`

Copied from:

```text
experiments/frequency_sweep/scripts/plain_spectre_helpers/extract_missing_outputs.sh
```

Purpose:

- Salvages runs where Spectre completed and created `psf/`, but export failed.
- Iterates over existing `cases/*/psf/` directories.
- Calls `run_export_case.sh` for cases missing `output_signals.txt`.

Usage:

```bash
./refresh_spectre_runtime.sh
source ./setup_spectre_env.sh
check_export_runtime
./extract_missing_outputs.sh
find cases -name output_signals.txt | wc -l
```

Use this when there is no reason to rerun Spectre.

---

### 5.9 `monitoring_commands.sh`

Generated run-local helper.

Purpose:

```bash
./monitoring_commands.sh progress
```

prints, every 10 seconds:

- count of `output_signals.txt`
- count of done cases
- count of failed cases
- relevant log tails from worker logs

Count-only usage:

```bash
./monitoring_commands.sh count
```

---

### 5.10 `run_template_ocean.sh` and `ciw_template_command.il`

Generated run-local helpers for regenerating the Spectre netlist template.

Most runs do not need to regenerate the template. If the existing ADE/Spectre netlist is valid and current, use:

```bash
./import_template.sh
```

If the schematic changed and the template must be regenerated:

```bash
./run_template_ocean.sh
```

If the shell says:

```text
ocean not found in this shell
```

then use:

```bash
cat ciw_template_command.il
```

and paste the contents into the Cadence CIW.

## 7. Case naming and assignment

Each case row in `cases.csv` includes:

```text
case_id, run_name, st1_file, st2_file, case_dir
```

Typical case directory:

```text
cases/st1_1_hz__st2_1_hz__trial_1/
```

Parallel assignment is deterministic:

```text
worker j receives all cases where case_id % NUM_JOBS == j
```

Changing `NUM_JOBS` changes worker assignment but not the underlying case definitions.


Then kill only the run-specific processes if necessary.

## 10. Maintenance notes

1. Keep one stable startup script in `experiments/frequency_sweep/bin/`.
2. Keep current helpers in `experiments/frequency_sweep/scripts/plain_spectre_helpers/`.
3. Move obsolete prototype scripts into a deprecated folder or delete them after a successful short regression run.
4. Do not edit run-directory scripts and expect the repo scripts to change; run directories are copies.
5. If the schematic or signal names change, update:
   - the template-generation OCN if needed;
   - the explicit parameter block in `import_template.sh` generation;
   - `export_psf_to_txt.ocn` signal names.
6. If a new design variable is introduced in OCEAN, add it to the Spectre parameter patch as well.
